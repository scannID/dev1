## Technical Details

### Receipt Number Generation
- **Format:** `RCT-YYYYMMDD-XXXX`
- **Example:** `RCT-20260709-0001`
- **Auto-incrementing:** Resets daily at midnight
- **Generated by:** PostgreSQL trigger on INSERT

### JSONB Storage
- `items` field stores line items as JSONB
- `metadata` field for extensibility
- Hibernate `@JdbcTypeCode(SqlTypes.JSON)` annotation for proper mapping

### Email Configuration
Configure SMTP in `application.yml`:

```yaml
spring:
  mail:
    host: smtp.gmail.com
    port: 587
    username: your-email@gmail.com
    password: your-app-password
    properties:
      mail:
        smtp:
          auth: true
          starttls:
            enable: true
            required: true
```

For development/testing, use [MailHog](https://github.com/mailhog/MailHog):
```yaml
spring:
  mail:
    host: localhost
    port: 1025
```

### Email Template
Professional HTML email with:
- Business branding
- Receipt details (number, date, customer)
- Itemized line items
- Subtotal, tax, service fee breakdown
- Total amount prominently displayed
- Professional footer

## Database Schema

### Receipts Table
```sql
CREATE TABLE receipts (
    id BIGSERIAL PRIMARY KEY,
    receipt_number VARCHAR(50) UNIQUE NOT NULL,
    
    -- Payment references
    order_id VARCHAR(100),
    ticket_id BIGINT,
    quick_payment_id BIGINT,
    device_payment_id BIGINT,
    
    -- Business details
    business_id VARCHAR(100) NOT NULL,
    business_name VARCHAR(200) NOT NULL,
    merchant_id VARCHAR(100) NOT NULL,
    
    -- Customer details
    customer_name VARCHAR(200),
    customer_email VARCHAR(200),
    customer_phone VARCHAR(50),
    
    -- Payment details
    amount DECIMAL(12, 2) NOT NULL,
    currency VARCHAR(10) DEFAULT 'UGX',
    payment_method VARCHAR(50),
    payment_reference VARCHAR(200),
    payment_date TIMESTAMP NOT NULL,
    
    -- Receipt items (JSONB)
    items JSONB,
    
    -- Totals
    subtotal DECIMAL(12, 2),
    tax_amount DECIMAL(12, 2) DEFAULT 0,
    service_fee DECIMAL(12, 2) DEFAULT 0,
    total_amount DECIMAL(12, 2) NOT NULL,
    
    -- Status
    status VARCHAR(20) DEFAULT 'GENERATED',
    
    -- Delivery tracking
    email_sent BOOLEAN DEFAULT FALSE,
    email_sent_at TIMESTAMP,
    email_error TEXT,
    in_app_viewed BOOLEAN DEFAULT FALSE,
    in_app_viewed_at TIMESTAMP,
    
    -- PDF generation
    pdf_generated BOOLEAN DEFAULT FALSE,
    pdf_url TEXT,
    pdf_generated_at TIMESTAMP,
    
    -- Metadata
    notes TEXT,
    metadata JSONB,
    
    -- Timestamps
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## Integration with Existing Systems

### Order Payment Integration
When an order payment status changes to "Paid":
1. `OrderService.updatePaymentStatus()` is called
2. Service checks if old status was not "Paid" and new status is "Paid"
3. Automatically calls `autoGenerateReceipt(order)`
4. Receipt is created with:
   - Order ID
   - Customer details
   - Itemized line items
   - Total amount
5. Receipt is saved to database
6. Email can be sent if customer email is available

### Future Integrations

## Performance Considerations

### Database Indexes
All critical fields indexed:
- `receipt_number` (unique index)
- `order_id`, `ticket_id`, `quick_payment_id`
- `business_id`, `customer_email`
- `payment_date`, `created_at` (DESC for sorting)

### Email Sending
- Async email sending (non-blocking)
- Retry logic via `receipt_delivery_attempts`
- Graceful degradation if email fails
- Configurable timeout

### Query Optimization
- Use specific queries (`findByOrderId`, `findByBusinessId`)
- Avoid N+1 queries
- Paginate large result sets if needed
